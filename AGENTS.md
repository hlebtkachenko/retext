# Retext

Native macOS menu-bar app: select text anywhere, press ⌥Space and type an instruction or pick an action (Fix grammar, English, a translation into the Mac's language, or your own), or press ⌥1…⌥9 directly; the selection is replaced in place by the active provider (Settings → Engine): Claude Code `claude -p` (default; quality level Medium = the `haiku` alias, High = `sonnet`, Max = `opus`), ChatGPT through the Codex CLI `codex exec` (the user's ChatGPT login), or an OpenAI-compatible API (key in the Keychain). Every bar starts at the default level from Settings, Up/Down change it for one run, ⌥N runs at the default level. Claude Code and Codex use the user's own login: subscription usage counts against the plan's limits.

- Stack: Swift 6 package (language mode 6), SwiftUI + Liquid Glass (macOS 26+), AppKit NSPanel, CGEvent tap for shortcuts, Accessibility API. No dependencies.
- Targets: `RetextCore` (pure logic: settings, routing, prompts, cache key, history, usage; tested), `Retext` (the app), `RetextCoreTests` (Swift Testing).
- Data: `~/Library/Application Support/Retext/` holds `settings.json`, `history.json` (cache + Recent, last 20), `usage.json` (per day, last 90 days), `codex-home/` (private CODEX_HOME: Retext creates only the `auth.json` symlink to Codex's own and the empty `work/`; Codex keeps its state and logs there, no conversations with `--ephemeral`). The custom API key is in the Keychain, per server (service = the bundle id `dev.hapd.retext`, account `custom-api-key:<scheme>://<host>[:port]`); it is only ever sent to that server. A key in the legacy `co.hleb.retext` service (1.4.0 and earlier) is moved there on first use and the old item deleted. The GitHub repo slug (update check) is the `RetextRepository` key in `Info.plist`; a fork changes only that key.
- Provider smoke test (real calls, no cache or history): `build/Retext.app/Contents/MacOS/Retext --provider-smoke claude|chatgpt|custom medium|high|max`; custom reads `RETEXT_SMOKE_BASE_URL`, `RETEXT_SMOKE_MODEL`, `RETEXT_SMOKE_KEY`.
- Build and install: `./build.sh` (installs to `~/Applications` and unregisters `build/Retext.app` from Launch Services, so the login item points to the installed copy; running the build copy registers it again). `./build.sh --no-install` builds only. Signing identity: `$RETEXT_SIGN_IDENTITY`, else the untracked `.sign-identity` file (one line, the identity name), else ad-hoc (`-`). A real identity keeps the Accessibility grant across rebuilds; ad-hoc builds lose it each time. Never commit an identity name.
- UI preview without a selection: `build/Retext.app/Contents/MacOS/Retext --demo menu|working|done|error|empty|nochange|welcome` (`--demo menu max` shows another level), or `--demo settings [actions|styles|words|engine|general|usage]` (the start of the pane title works too: `app`, `protected`). Demo prints the `screencapture` rectangle or window number. The welcome demo never marks Retext as onboarded.
- Gate: `swift build` and `swift test` must pass; check UI changes with `--demo` screenshots.
- E2E with synthetic keys: confirm the frontmost app and document are your own scratch TextEdit or Preview file before every keystroke.
- Release: for now a tag and a GitHub release without assets (users build from source). The signed DMG (`scripts/release.sh`, the manual `release.yml` workflow, the Homebrew cask, GitHub Pages) is planned and not used yet, see docs/RELEASING.md. Never notarize or tag without the owner's go.
- Eval: `python3 -I eval/run.py`. Re-run it after editing prompts or add-ons. It uses the owner's Claude subscription.
- See ARCHITECTURE.md for the flow.
