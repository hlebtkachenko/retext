# Retext

Native macOS menu-bar app: select text anywhere, press the bar shortcut (⌥Space by default) and type an instruction or pick an action (Fix grammar, English, a translation into the Mac's language, or your own), or press ⌥1…⌥9 directly; the selection is replaced in place by the active provider (Settings → AI): Claude Code `claude -p` (default; quality level Medium = the `haiku` alias, High = `sonnet`, Max = `opus`), ChatGPT through the Codex CLI `codex exec` (the user's ChatGPT login), or an OpenAI-compatible API (key in the Keychain). Every bar starts at the default level from Settings, Up/Down change it for one run, ⌥N runs at the default level. Claude Code and Codex use the user's own login: subscription usage counts against the plan's limits.

- Stack: Swift 6 package (language mode 6), SwiftUI + Liquid Glass (macOS 26+), AppKit NSPanel, CGEvent tap for shortcuts, Accessibility API. No dependencies.
- Targets: `RetextCore` (pure logic: settings, routing, prompts, cache key, history, usage, identity and the Keychain move, the preview's text diff; tested), `Retext` (the app), `RetextCoreTests` and `RetextTests` (the app's subprocess runner, command lookup, shortcut key codes, hotkey flags and GitHub mark; Swift Testing).
- Data: `~/Library/Application Support/Retext/` holds `settings.json`, `history.json` (cache + Settings → History: each result's full selection and answer with its action, app, level, provider, model, effort, tokens, cost and duration, as many as `historyRetention` keeps: Off keeps no results on disk (the file is emptied) and keeps the last result in memory only, else the last 20 (default), the last 60 or all; plain JSON, saved 0.5 s after a change and at quit), `usage.json` (per day, last 90 days), `instance.lock` (single-instance flock: a second launch shows the running copy's Settings and exits 0; `--demo` and `--provider-smoke` skip it), `codex-home/` (private CODEX_HOME: Retext creates only the `auth.json` symlink to Codex's own and the empty `work/`; Codex keeps its state and logs there, no conversations with `--ephemeral`). The custom API key is in the Keychain, per server (service = the bundle id `dev.hapd.retext`, account `custom-api-key:<scheme>://<host>[:port]`); it is only ever sent to that server. A key in the legacy `co.hleb.retext` service (1.4.0 and earlier) is moved there on first use (added only, never over an existing item) and the old item deleted. The GitHub repo slug (update check, About links) is the `RetextRepository` key in `Info.plist`, and the website link in About is `RetextWebsite`. A fork that ships its own build changes those keys and `CFBundleIdentifier` too; otherwise it shares the Keychain items, preferences, Accessibility grant and login item with upstream, and its Keychain move would take upstream users' legacy key.
- Provider smoke test (real calls, no cache or history): `build.noindex/Retext.app/Contents/MacOS/Retext --provider-smoke claude|chatgpt|custom medium|high|max`; custom reads `RETEXT_SMOKE_BASE_URL`, `RETEXT_SMOKE_MODEL`, `RETEXT_SMOKE_KEY`.
- Build and install: `./build.sh` (builds `build.noindex/Retext.app`, waits for the running Retext to quit, installs to `~/Applications`, moves files a build no longer makes out of the build and installed apps into `build.noindex/replaced/<time>/` (never deleted), verifies the installed signature and unregisters `build.noindex/Retext.app` and the old `build/Retext.app` from Launch Services, so the login item points to the installed copy; running the build copy registers it again). `./build.sh --no-install` builds only. Signing identity: `$RETEXT_SIGN_IDENTITY`, else the untracked `.sign-identity` file (one line, the identity name), else ad-hoc (`-`). A real identity keeps the Accessibility grant across rebuilds; ad-hoc builds lose it each time. Never commit an identity name.
- UI preview without a selection: `build.noindex/Retext.app/Contents/MacOS/Retext --demo menu|working|done|error|empty|nochange|preview` (`--demo menu max` shows another level, `--demo preview long` a long preview); `--demo onboarding [welcome|access|provider|shortcut]` (an Onboarding step; `--demo welcome` is the older name and opens the first step); or `--demo settings [about|general|actions|styles|words|ai|history]` (the aliases `overview`, `engine`, `usage` and `app` and the start of a pane title, such as `per` or `protected`, work too; an unknown name opens About). A word after the pane opens a state for screenshots: `about update` (a found update, without asking GitHub), `general reset` (the Reset All Settings confirmation), `general record` (the shortcut recorder), `general reject` (the recorder refusing ⌘C), `actions expand` (the first action's editor sheet), `actions icons` (its icon picker), `actions restore` (the Restore Default Actions confirmation), `ai claude|chatgpt|custom` (that provider's settings), `history results` (scrolled to the results), `history detail` (the first result's details), `history changes` (the same with Show Changes on), `history old` (an older, shortened entry), `history clear` (the Clear History confirmation), `history off` (the Turn Off History confirmation). `--dark` shows dark mode: put it after the pane and state, but before `max` or `long`, which must stay last (`--demo menu --dark max`). Demos use sample settings, history and usage (`DemoData`) and never read or write the files in Application Support. Demo prints the `screencapture` rectangle or window number; demo windows open behind other windows (no Dock icon, no focus), so capture with `-l <window>`, or with `-R` only when nothing else overlaps. A demo quits after 30 s. Run demos from a private copy, never from the shared build folder: `ditto build.noindex/Retext.app "$TMPDIR/<name>.noindex/Retext.app"`, then `lsregister -u` that copy after use (`/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister`). The onboarding demo never marks Retext as onboarded.
- Gate: `swift build` and `swift test` must pass; check UI changes with `--demo` screenshots.
- E2E with synthetic keys: confirm the frontmost app and document are your own scratch TextEdit or Preview file before every keystroke.
- Release: for now a tag and a GitHub release without assets (users build from source). The signed DMG (`scripts/release.sh`, the manual `release.yml` workflow, the Homebrew cask, GitHub Pages) is planned and not used yet, see docs/RELEASING.md. Never notarize or tag without the owner's go.
- Eval: `python3 -I eval/run.py`. Re-run it after editing prompts or add-ons. It uses the owner's Claude subscription.
- See ARCHITECTURE.md for the flow.
