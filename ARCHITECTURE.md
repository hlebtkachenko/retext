# Architecture

## Flow
Launch: `RetextMain` (the `@main` entry, `RetextApp.swift`) first calls `SingleInstance.claim()`: an exclusive `flock` on `~/Library/Application Support/Retext/instance.lock` (close-on-exec, held until the process exits). If another Retext holds it (5 retries, 200 ms apart, for one still quitting), it posts the `<bundle id>.reopen` distributed notification, prints "Retext is already running; showing its Settings." and exits 0; the running copy shows Settings. `--demo` and `--provider-smoke` skip the lock. `--demo` windows open behind other windows with no Dock icon and never become key (`AppWindows.isDemo`), and the demo quits after 30 s (`exit`, so an open sheet or dialog can't hold it). A demo `AppState` starts from `DemoData` (sample settings, history and usage) and never reads or writes the files in Application Support. Otherwise, launch shows Onboarding when `onboarded` is false, and asks for Accessibility at launch only when it is true (a new user is asked in Onboarding's Accessibility step).

1. `Hotkeys` (a session `CGEvent` tap) always takes the bar shortcut (`RetextSettings.barShortcut`: a key code and modifiers, ⌥Space by default, set in Settings → General, matched with exact modifiers), so it wins over another app's hotkey for the same combo. The tap needs Accessibility; until it runs, the bar shortcut is a Carbon hotkey (`RegisterEventHotKey`, no Accessibility needed; never in a demo, ignored while `paused`) that opens Settings → About, whose Accessibility row says how to grant it, so the key never reaches the front app (⌥Space would type a no-break space over the selection). It follows shortcut changes and is removed when the tap starts; a failed registration (another app holds the combo) is logged and skipped. ⌥1…⌥N (N = number of actions) are taken only when the frontmost app's focused element has a non-empty selection, read from `AXSelectedText`, else from WebKit's text-marker selection (`AXSelectedTextMarkerRange`, as in Mail and Safari) (0.1 s AX timeout); otherwise the key passes through, so Czech ⌥2 = @ still types. The bar shortcut calls `PopupController.trigger()` (menu); ⌥N calls `trigger(index)` and skips the menu (with the menu open, it runs on the selection already read). A trigger while a read is in flight is ignored. While the Shortcut row records a new shortcut, `Hotkeys.paused` lets every key through, so the current shortcut can be recorded too; every way out of recording (a key, Esc, a second click on the field, leaving the pane or the window) turns it off.
2. `SelectionIO.read()` sends ⌘C to get the selected text plus the RTF attributes of its first character, then restores the clipboard; Accessibility on the source app's focused element gives the screen bounds, and the text when ⌘C yields nothing. A ⌘C that hasn't landed after 400 ms is watched until 1.5 s; a late copy is undone too, unless its text differs from the Accessibility text (the user copied something else). `PopupController.trigger` then refuses a selection over `Engine.maxSelectionLength` (50,000 characters) with "Selection too long (over 50,000 characters)", before the bar opens.
3. `PopupController` shows a non-activating `KeyPanel` hosting `PopupView`: a Liquid Glass capsule with an instruction field (focused, an AppKit `NSTextField`) followed by the action buttons, 8 pt below the selection, left-aligned, flipped above when there is no room, under the whole text field when the app's selection bounds are missing or fall outside the field (Electron and web apps), at the mouse pointer when neither is known. The panel takes the hosting view's fitting size and only grows while open. Typing goes to the field; ←/→ move to the buttons only while it is empty; Return runs the instruction or the highlighted button. A chip at the right end shows the quality level: it starts at the default level each time the bar opens, ↑/↓ step it (clamped, wherever the highlight is, without moving the cursor), a click cycles it. Electron apps expose their tree only after `AXManualAccessibility` is set: with "Improve Electron App Support" on (default), Retext sets it on every app switch so the ⌥N check works before the first bar; off, it is set only when the tap or `SelectionIO.read()` reads. AX calls use a 0.1 to 0.2 s messaging timeout. The original app stays frontmost.
4. `Engine` (RetextCore) builds a `Job` for the active `Provider` and the run's `Level` (the bar's level, or the default level for ⌥N without the bar): model and effort from `RetextSettings.model(for:)` (Claude Code: Medium `haiku`, High `sonnet`, Max `opus`, model and effort overridable per level in `claudeModels`; ChatGPT: built-in `Codex.defaultModels`, overridable per level in `chatGPTModels`; both overrides fall back to the built-in value per field, so an effort can be changed alone; Custom: the user's model per level) and system prompt (task + the level's add-on for High and Max + content rules + protected words + the style for the frontmost app's bundle id).
5. Cache: the key is SHA-256 of provider (Custom adds its base URL) + model + effort + prompt version + system prompt + text. A hit in the in-memory history skips the provider and counts as a cache hit (with Keep set to Off, the history holds only the last result, in memory, so the cache covers that one). Otherwise `ProviderRunner` sends the job to the active provider's runner. Claude Code: `ClaudeRunner` runs `claude -p --model <level model> --effort <level effort> --output-format json` with user settings, hooks, plugins, MCP and tools disabled; `claude` is the Settings path override, else `command -v claude` in a login shell (cached once found; a miss, or a cached path that is no longer executable, is looked up again on the next run, and the shell is stopped after 3 s), else the usual install paths. Text goes in on stdin inside a tag with a random suffix (`<text-1a2b3c4d>`), so selected text can't close the block; timeout per level (`Level.timeout`: 60 s at Medium and High, 120 s at Max), Esc cancels; a stop sends SIGTERM, then SIGKILL after 2 s to the process group. Failures are sorted from the JSON `result` and stderr into not found, not logged in, usage limit, unknown model or other (`ClaudeFailure`). `result`, tokens and `total_cost_usd` (≈ list price) are recorded in `usage.json`, and, after `Engine.checkLayout` accepts it, in the history: a `HistoryEntry` with the whole selection and result, the action's title and kind, app, level, provider, model, effort, tokens, cost and the run's duration (timed around the provider call). `History.add` keeps `HistoryRetention.memoryLimit` entries (Off keeps 1, in memory only); `AppState` saves `History.persisted(for:)` (nothing when Off) to `history.json` on a serial background queue 0.5 s after the last change, so recording never delays the paste, and flushes a pending save when Retext quits. At launch, history.json is trimmed to the retention and saved back when that changed it. A rejected answer is never recorded, so it can't come back as a cache hit. ChatGPT: `CodexRunner` runs `codex exec --ephemeral --json` (`Codex.arguments`; no session files) with `-s read-only` (no file writes), the shell and other tool features `--disable`d (read-only alone still let the model run shell commands), web search off, the skills list left out of the prompt (`skills.include_instructions=false`), the system prompt as `developer_instructions` (a TOML basic string, `Codex.tomlString`), and `CODEX_HOME` set to `~/Library/Application Support/Retext/codex-home`, where Retext creates only a symlink `auth.json` to Codex's own (Codex writes its own state and logs there) (`$CODEX_HOME` from the app or the login shell, else `~/.codex`), so the user's config, `AGENTS.md` and MCP stay out and token refreshes land in the real file; its working directory is the empty `codex-home/work`, so no project `AGENTS.md` is picked up either; the codex directory goes first on `PATH`, since an npm install is a Node script. The result is the last `agent_message` in the JSONL, tokens come from `turn.completed`; `turn.failed`/`error` lines are sorted by `Codex.classify` (a 401 is not logged in, "model is not supported" an unknown model). Custom: `APIRunner` POSTs to `{base}/chat/completions` (`OpenAICompatible.body`) with the Keychain key saved for that endpoint's scheme, host and port (`CustomProviderSettings.keyAccount`) as a Bearer token, so a base URL pointed at another server gets no key; an http URL works only for a local or private-network host (`CustomProviderSettings.isLocal`, which also makes the key optional), and redirects are followed only to the same scheme, host and port (`OpenAICompatible.allowsRedirect`); 401/403 is a rejected key, 429 the limit, a 404 about the model an unknown model; `finish_reason` "length" (cut off at the output limit) fails with `ClaudeFailure.cutOff`, like Claude Code's `stop_reason` "max_tokens": `ClaudeOutput.checkComplete()` runs after the call is recorded in `usage.json`, so a cut-off answer counts but is never pasted or cached. Both have the same per-level timeouts and Esc cancel as Claude Code; the answer is recorded the same way, with no cost.
6. `Engine.checkLayout` (grammar and translate only): a one-line input whose result has line breaks gets them joined into one line, unless an app style applies (it may ask for a layout); a grammar result longer than 1.5 × input + 20 characters is treated as containing extra text (a note to the user) and fails with `ClaudeFailure.extraText`, so nothing is pasted. Typed instructions pass through. Then, if the normalized result equals the normalized input, a "No changes needed" bubble shows and nothing is pasted or copied. With "Preview Before Replacing" on (Settings → General, off by default), and only after the checks in step 8 (editable, no attachment, still selected; read-only text and the other cases are copied without a preview) and while the selection's app is still frontmost (else the result is copied), the bar shows the result with the changes marked (`TextDiff`: inserted words highlighted, deleted ones struck through) and waits: Return or the Replace button goes on to the paste below once Return is released, Esc or Discard discards the result, ⌘C or Copy copies it. A click elsewhere, a switch to another app or any Retext shortcut also discards it (`--demo preview`, `--demo preview long`).
7. `SelectionIO.replace()` puts the result on the clipboard as RTF in the original attributes plus plain text (marked transient), re-activates the app, sends ⌘V and returns; 1.5 s later an unstructured task (so cancelling the run can't shorten the wait) restores the old clipboard, only if the clipboard still holds the result (same change count or same string), marked `org.nspasteboard.TransientType` so clipboard managers skip it. The next read or paste waits for a pending restore (`SelectionIO.restoring`). Rich-text apps keep the original font, size and colour; plain-text fields take the plain string. ⌘Z undoes it.
8. If the selection is read-only (no text role, `AXSelectedText` not settable, no `AXEditableAncestor`: web pages, PDFs, received mail), holds an image or other attachment (`Selection.hasAttachment`: U+FFFC in the AX text or the copied plain text, or an attachment in the copied RTF or RTFD; pasting text would turn a Mail signature image into its file name), or changed while the provider worked (checked on the source app, not the system-wide focus, which can be Retext's field; compared with the Accessibility text from the read, else with the copied text), the result is copied instead of pasted. While the "Copied" bubble shows (4 s), the event tap turns ⌘Z into "restore the previous clipboard"; outside that window ⌘Z is untouched.

## Files
- `Sources/RetextCore/Settings.swift`: `RetextSettings` (actions, default level, app styles, protected words, bar shortcut (`BarShortcut`: key code and modifiers, presets ⌥Space, ⌃⌥Space, ⌃⇧Space), claude path, preview, history retention (`HistoryRetention`: Off, Last 20, Last 60, Unlimited), Electron and update-check switches, `onboarded`), defaults (the third action follows the Mac's first language), the built-in prompt per action kind (Reset Prompt), protected-word list parsing, JSON load and save (load moves untouched 1.2.0 default prompts and the old Mail style to the current defaults), import validation (must decode and have `actions`), `Store` paths. `onboarded` decodes as true when the key is missing, and load sets it when settings.json is missing but history.json or usage.json exists, or when settings.json can't be decoded (load first copies it to `settings.json.invalid`, keeping an earlier copy), so only a new install sees Onboarding. Keys of older files are read once and never written: `keepHistory` (true becomes Last 20, false Off) and `menuShortcut` (`optionSpace`, `controlOptionSpace`); a saved `barShortcut` the recorder would refuse (`problem`: no ⌃, ⌥ or ⌘, an unknown modifier bit, or a reserved shortcut such as ⌘C) falls back to the default.
- `Sources/RetextCore/Shortcut.swift`: the bar shortcut's labels (`displayLabel` such as "⌃⌥K", `spokenLabel` for VoiceOver; the key's character comes from the current keyboard layout through `characterLookup`, set by the app, else the US layout) and `problem`, why a shortcut is refused: no modifier or only ⇧, ⌘C, ⌘V, ⌘Z, ⌥1…⌥9, ⌘Space, ⌃Space, ⌥⌘Space (exact modifiers, like the tap).
- `Sources/RetextCore/ProtectedWords.swift`: `editProtectedWord`, an in-place edit that splits a list into several words and drops words already in the list (an empty or duplicate edit removes the row).
- `Sources/RetextCore/Engine.swift`: `Level` (model, effort, prompt add-on), the selection size limit (`maxSelectionLength`), `ClaudeFailure.cutOff`, model short names, system prompt, boundary-tag wrapper, cache key, no-change normalization, `claude -p` JSON parsing, error classification and per-provider messages.
- `Sources/RetextCore/Providers.swift`: `Provider`, `ProviderModel`, `CustomProviderSettings` (base URL, models, presets), `RetextSettings.model(for:)`, `Codex` (default models, `codex exec` arguments, TOML escaping, JSONL parsing, `debug models` list, error classification), `OpenAICompatible` (request body, response and error parsing, HTTP status mapping).
- `Sources/RetextCore/LevelTimeout.swift`: `Level.timeout`, how long one `claude -p` run may take.
- `Sources/RetextCore/Updates.swift`: `Release` (GitHub's `releases/latest` answer) and `Version.isNewer` (tag vs. `CFBundleShortVersionString`).
- `Sources/RetextCore/Identity.swift`: `Identity` (bundle id, legacy Keychain service `co.hleb.retext`, the `RetextRepository` slug and the GitHub URLs built from it) and `KeychainMigration` (moves a legacy key to the current service: add only, never over an existing item, read back, then delete the old item; when the add fails the legacy item stays and the current item wins if readable; when the current item exists but its read is denied, there is no key and the legacy item is not touched, so the user sees one Keychain prompt).
- `Sources/RetextCore/TextDiff.swift`: the preview's diff. Tokens are runs of letters and digits, runs of whitespace and single other characters; a run longer than 16 characters (text without spaces) is split into characters. The common prefix and suffix are trimmed, then an LCS over token ids (UInt16 cells) marks the middle; above 16M cells the middle is shown as one removed block and one added block.
- `Sources/RetextCore/History.swift`: history and cache in one list, newest first. `HistoryEntry` holds the whole selection and result, title, kind, app, level, provider, model, effort, tokens, cost and duration; the fields added after 1.4.0 are optional, so older files decode. 1.4.0 and earlier saved the whole selection; builds from main between 1.4.0 and full history saved only its first 60 normalized characters, so an entry without a level and with exactly `legacyInputLimit` (60) characters is shown as shortened (`isShortened`). `History.add` replaces an entry with the same key and trims to `HistoryRetention.memoryLimit`; `persisted(for:)` is what the file holds (nothing when Off); compact JSON; a history.json that can't be decoded is first copied to `history.json.invalid` (an earlier copy is kept), then history starts empty. Per-day usage counters (last 90 days) and their totals over the last N days.
- `Sources/Retext/RetextApp.swift`: `RetextMain` (the `@main` entry) and `SingleInstance` (the lock and the reopen notification), the menu-bar menu (actions with ⌥N that run on the selection; a red row, with a red symbol for menus that ignore the color, only when the active provider can't run, opening Settings → AI; History… (Settings → History), Settings… ⌘, and "Check for Updates…", or "Update Available (x.y.z)…" once a newer release is known, which opens Settings → About and checks there; Quit Retext), the main menu shown while Settings or Onboarding is open (About Retext, Check for Updates… and Settings… ⌘, in the app menu, Retext Onboarding in Help); the icon is an "R" with a text cursor; `isInserted` binding writes only real changes, since SwiftUI writes it back on every scene update), the `--demo` and `--provider-smoke` entry points, and the launch steps.
- `Sources/Retext/Hotkeys.swift`: the shortcut event tap (bar shortcut, ⌥1…⌥N with a selection, ⌘Z after a copy), `paused` while a shortcut is recorded, the mapping of `BarShortcut` modifiers to `CGEventFlags` and to Carbon modifier bits, and the Carbon fallback hotkey for the bar shortcut while the tap can't run (no Accessibility yet).
- `Sources/Retext/AppState.swift`: shared settings, history and usage. Settings and usage are saved on change; history is saved on a background queue 0.5 s after the last change and flushed at quit and on SIGTERM (`pkill`, which skips willTerminate), trimmed to the retention at launch and when the retention changes. In a demo it holds `DemoData` and saves nothing. Also the active provider's status (checked again when provider settings change), the available update, and the manual update check (Check Now and "Check for Updates…": running flag and last result, so a second check is not started while one runs and the result survives switching panes).
- `Sources/Retext/DemoData.swift`: what a `--demo` run shows instead of the user's files: the default actions in English plus two samples, two app styles, two protected words, a made-up history (including an older shortened entry) and usage.
- `Sources/Retext/Onboarding.swift`: `AppWindows` (the activation policy shared by Settings and Onboarding, and `isDemo`: demo windows open behind the others without focus), the Onboarding window (steps welcome, access, provider, shortcut; first launch, About's Onboarding row, Help → Retext Onboarding, `--demo onboarding [step]`; the access step moves on by itself once access is granted; closing it sets `onboarded`, except in a demo), and the live Accessibility and provider status rows used there and in Settings → About (the provider's path is shown with `~` for the home folder; while access is off, the Accessibility row says to remove Retext with − and add it again if it is already listed, since a new signature leaves a stale entry; a demo shows a fixed status).
- `Sources/Retext/Updates.swift`: `UpdateChecker`: at launch and 30 s after the Mac wakes, at most once a day and only with "Check for Updates Automatically" on, GETs `api.github.com/repos/<slug>/releases/latest`, where `<slug>` is the `RetextRepository` key in `Info.plist` (also used for the About links), so a fork changes that key (and `CFBundleIdentifier`, see AGENTS.md) (ephemeral session, `User-Agent: Retext/<version>`, nothing else). The last check time, latest version and its page are kept in `UserDefaults` (the bundle id's domain, `dev.hapd.retext`), so a relaunch the same day still shows the menu item. A `swift build` binary (no version) never checks. Check Now and "Check for Updates…" are a manual check: it ignores the daily limit and the automatic setting, and Settings → About shows up to date, a newer version (with Open Release Page) or why it failed (a 403 reads as the GitHub rate limit).
- `Sources/Retext/Popup.swift`: state model (including the run's level and the preview phase with its diff), SwiftUI view with the level chip, instruction field and the preview's Replace, Discard and Copy buttons, panel, placement, keyboard, click and app-switch handling, run flow (the pending result and selection while a preview waits).
- `Sources/Retext/SettingsView.swift`: the Settings window (`SettingsWindow`: `NSHostingController` with a unified `NSToolbar` and `sceneBridgingOptions` for title and toolbars), `SettingsNavigation` (the selected pane, shared so the menu, Check for Updates… and a second launch switch it without rebuilding the content, with back and forward stacks: `go(to:)` pushes the current pane and clears Forward, as in a browser; `goBack()` and `goForward()` back the toolbar's Back and Forward buttons, ⌘[ and ⌘]; a demo sets `pane` directly, with no history), and `SettingsView`: the sidebar (a Retext row with the icon, name and "About" or "Update Available" that opens About, then General, Actions, Per-App Styles, Protected Words, AI, History), a hard scroll edge under the toolbar and the `Pane` enum with the `--demo settings` names (case names, the aliases `overview`, `engine`, `usage` and `app`, or the start of a title; unknown opens About). The window title is the pane's name. Reset All Settings, Restore Default Actions, Delete Action, Clear History, Remove Key and lowering Keep ask first, with Cancel as the default. Switches to the `.regular` activation policy while open.
- `Sources/Retext/SettingsKit.swift`: shared Settings pieces: `IconRow` (an `IconTile`, the symbol in its tint on a neutral rounded square with a hairline border; title, optional subtitle, trailing controls; the sidebar keeps its colored tiles), `IconRow`'s optional `titleWidth` (a one-line title column, used by the AI pane's Models rows so their controls line up), `PageDescription` (the pane's first, header-only section: `Pane.summary`, one line of secondary text; every pane but About, which shows the summary in its hero), `SectionTitle` (section titles after `PageDescription`, which would otherwise draw small and secondary), `PopUpPicker` (with an optional width: fixed, or filling the offered width; a long title truncates) and `PullDownButton` (bordered pop-up and pull-down buttons as `NSPopUpButton` wrappers, because SwiftUI's `Picker` and `Menu` draw without a border in a grouped `Form` whatever their style; `PullDownItem` holds the menu's actions, headers and separators; a pull-down builds its menu from an `items` closure each time it opens) and `TestButton` (one tiny request at Medium with the input "ok", counted in usage).
- `Sources/Retext/SettingsAbout.swift`: `AppVersion` and the About pane: the hero (icon, name, the tagline `Pane.about.summary` in place of a `PageDescription`, version), an Onboarding row, Accessibility and provider status, Updates (automatic check toggle, last check and Check Now, the update card with Open Release Page, only for a github.com page), links (the `RetextWebsite` and `RetextRepository` keys of `Info.plist`: website, repository, changelog, new issue) and the trademark note.
- `Sources/Retext/SettingsGeneral.swift`: Open at Login (`SMAppService.mainApp`, off until the user turns it on; a note only while it waits for approval), Show in Menu Bar (`MenuBarExtra(isInserted:)`; its hint is a tooltip; with it off, reopening the app shows Settings via `applicationShouldHandleReopen`), the Shortcut row, Preview Before Replacing with `PreviewSample` (the real `PopupView` with a static model), Back Up Settings (export and import through `NSSavePanel`/`NSOpenPanel` in the settings.json format), Advanced (Improve Electron App Support) and Reset All Settings. Import and reset keep `onboarded` and `historyRetention`; import also keeps the Claude Code and Codex paths and the custom API base URL, so an imported file can't redirect the saved key.
- `Sources/Retext/SettingsShortcut.swift`: `ShortcutField` (the shortcut as keycaps, one per modifier and the key; a click records, another click or Esc cancels; the presets, the current custom shortcut and Record Custom… are in its context menu; reset to ⌥Space) and `ShortcutRecorder` (a local key monitor while recording, with `Hotkeys.paused` on; Esc cancels; a refused shortcut shows `BarShortcut.problem`; recording ends when the pane, window or app loses focus). Used in General and Onboarding.
- `Sources/Retext/SettingsEngine.swift`: the AI pane, in three sections. Provider: the provider pop-up and that provider's rows, with one footer: Claude Code path override and Test; Codex path override, ChatGPT login status and Test (checks `codex login status` first); custom API base URL with a Presets pull-down, API key (SecureField, saved to the Keychain, shown only as "Saved"; Remove… confirms) and Test. Default Effort: one row with no icon or section title, its segmented Medium, High, Max on the title's line. Models: one row per level for every provider, in the same columns (a title column as wide as the longest level title, the model control filling the rest, a 150 pt effort column), so the controls line up at any window width; the time limit is the row's tooltip. Claude Code and ChatGPT share `ModelRow`: a model and an effort pop-up, each starting with "Default (<built-in>)" (Claude Code: the `haiku`, `sonnet`, `opus` and `fable` aliases and the `claude --effort` values; ChatGPT: the models from `codex debug models`), plus the saved value when it isn't listed; the custom API has a model id and an optional effort field.
- `Sources/Retext/SettingsActions.swift`: the Actions pane: rows that drag with `onDrag`/`onDrop` and one `ReorderDropDelegate` (`onMove` does nothing in a grouped `Form` on macOS): the payload is the action id in a private type (`dev.hapd.retext.action-id`, visible to Retext only, so other apps take nothing and outside text drags are ignored); the dragged row moves live onto each row it enters, dimmed while it drags; the same delegate on the whole pane ends a drag dropped between rows, and a 200 ms check for no mouse button down ends one released outside the window; the row's content is a plain `Button` that opens the editor; Move Up and Move Down in the context menu and as VoiceOver actions; a sheet editor on a copy of the action (title, icon picked from 20 symbols with short names, kind, a `TextEditor` prompt where Return starts a new line, Insert Example, Reset Prompt, Delete Action… confirmed inside the sheet), Add Action (up to 9) and Restore Default Actions….
- `Sources/Retext/SettingsStyles.swift`: the Per-App Styles pane: an app menu from running apps and /Applications, ~/Applications, /System/Applications (scanned off the main thread), with icons; each style has a header row (the app's icon, name and bundle id, or "No app chosen"; a Change App pull-down; Remove, a − icon) above its style field.
- `Sources/Retext/SettingsWords.swift`: the Protected Words pane: a multi-line add field that takes the focus (one word per line or separated by commas) and rows editable in place, saved on Return or when the field loses focus (`editProtectedWord`), and Paste List…, a sheet for a long list (`addProtectedWords`; words already in the list are skipped; `--demo settings words paste`).
- `Sources/Retext/SettingsHistory.swift`: the History pane: Keep, a pop-up (lowering it below the saved count, or Off, asks first), a Clear History row (Clear… confirms), Usage (a segmented period, Today, 7 Days, 30 Days or 90 Days, 30 at first, over three figures: Runs, Tokens, Price), and History (N), the results with search, shown 100 at a time, each a plain button row with a chevron that opens its details (Show Details, Copy Result, Copy Original and Delete in its context menu); `HistoryDetail`, a sheet with the full original and result, each with a copy icon (a checkmark for 1.5 s after copying), Show Changes under the result (uses `TextDiff`), every field of the entry, and Delete and Done.
- `Sources/Retext/GitHubMark.swift`: the GitHub mark as a SwiftUI `Shape`, parsed from Primer Octicons' `mark-github-16` SVG path (`SVGPath`: M L H V C S Z and circular arcs), so no image asset is needed.
- `Sources/Retext/Selection.swift`: Accessibility read, clipboard fallback, paste.
- `Sources/Retext/Claude.swift`: `claude` discovery, `claude --version`, and the `claude -p` runner.
- `Sources/Retext/Codex.swift`: `codex` discovery (login shell, Homebrew, `~/.local/bin`, nvm), the private CODEX_HOME, the `codex exec` runner, `codex login status`, `codex --version` and `codex debug models`.
- `Sources/Retext/API.swift`: the OpenAI-compatible runner (ephemeral URLSession, whole-call timeout) and `Keychain` (the custom API keys, generic passwords, service = the bundle id `dev.hapd.retext`, account `custom-api-key:<scheme>://<host>[:port]`; on first use a key in the legacy `co.hleb.retext` service is added there, never over an existing item, and the old item deleted after a read-back).
- `Sources/Retext/CLI.swift`: `CommandLocator` (override, login shell `command -v` stopped after 3 s, candidates; only hits are cached) and `Subprocess.run` with `Subprocess.Child` (stdin written on its own task, stdout and stderr read as they arrive; reports once, when the process has exited and both pipes reached EOF, or 0.5 s after exit, so a background job can't hold the run; a stop on cancel or timeout sends SIGTERM, then SIGKILL after 2 s to the process group) shared by Claude Code and Codex.
- `Sources/Retext/ProviderRunner.swift`: dispatch to the active provider's runner, and `ProviderStatus` (local readiness check for the menu, Onboarding and Settings → About).
- `Tests/RetextCoreTests`: Swift Testing tests of RetextCore, including history retention and decoding of older files (`HistoryTests`), shortcut labels and refusals (`ShortcutTests`), protected-word edits (`ProtectedWordsTests`) and the settings migrations (`EngineTests`). `Tests/RetextTests`: tests of the app target (`@testable import Retext`): `Subprocess` stop and timing, large input, `CommandLocator` caching, the shortcut key codes against Carbon's `kVK_*` (`ShortcutKeyCodesTests`), the tap's key and flags for a `BarShortcut` (`HotkeysTests`), the shortcut field's keycaps (`ShortcutFieldTests`) and the GitHub mark's path (`GitHubMarkTests`).
- `build.sh`: builds `build.noindex/Retext.app` (`.noindex` keeps Spotlight from offering the build copy), signs it (with `$RETEXT_SIGN_IDENTITY`, else `.sign-identity`, a name or SHA-1 hash, else ad-hoc, after which it warns that Accessibility must be granted again), waits for the running Retext to quit (it holds the single-instance lock), installs it to `~/Applications`, verifies the installed signature, unregisters the build copies (including the old `build/`) from Launch Services and starts it.
- `Resources/AppIcon.icon`: the Liquid Glass app icon (Icon Composer format: solid brand fill, R and cursor layers with glass). `build.sh` and `scripts/release.sh` compile it with `actool` into `Assets.car` (needs Xcode 26 or later) and fail if that step fails. `Resources/AppIcon.icns` is the full-size fallback rendered from it.
- `scripts/make-icon.swift`: writes the icon's glyph SVGs, renders `AppIcon.icns` from the compiled glass icon and the launch images in `docs/images/`.
- `scripts/release.sh` (planned signed release, not used yet): builds a universal app, signs it with Developer ID, notarizes and staples it, and packs it into a signed, notarized DMG (see `docs/RELEASING.md`).
- `.github/workflows/release.yml` (not used yet): run by hand for a tag (`workflow_dispatch`), runs `scripts/release.sh` and attaches the DMG to the GitHub release; skips the whole run when the release already has `Retext-VERSION.dmg`, so published assets are never overwritten.
- `Casks/retext.rb`: template of the Homebrew cask for the owner's tap (`<owner>/tap`; planned, not published yet).
- `docs/index.html`: the landing page (GitHub Pages, not published yet).
- `eval/`: prompt eval set for the quality levels and prompts; see `eval/README.md`.

## Decisions
- Native app over Hammerspoon: SwiftUI Liquid Glass needs a real app; it also removes a dependency.
- ChatGPT through the Codex CLI, not the OpenAI API: it uses the ChatGPT subscription the user already has, and Retext keeps handling no OpenAI credentials (Retext only links the private CODEX_HOME's auth.json to Codex's own, never reads it).
- Every other model through one OpenAI-compatible client: OpenRouter, Ollama, LM Studio, Gemini, Mistral and Groq all speak Chat Completions, so one runner with a base URL covers them. Its key goes to the Keychain, not settings.json, so exporting settings never leaks it, and it is bound to the host it was saved for, so changing or importing a base URL never sends it elsewhere.
- One active provider, not a provider per action or level: the levels stay one switch, and the bar works the same whichever provider runs.
- `claude -p` over a built-in API client: Retext never handles Claude credentials. Uses your own Claude Code login: subscription usage counts against your plan's limits; API-key logins are billed to your account. Cost shown is the list-price equivalent.
- Paste via clipboard over AX `setValue`: works in every app and keeps native undo.
- Plain-text paste was dropped: Mail fell back to its default Helvetica instead of the selection's font.
- Event tap over Carbon `RegisterEventHotKey`: Carbon fails when another app holds the combo; the tap takes precedence. Carbon is only the stand-in until Accessibility is granted, since without it the shortcut would type into the front app.
- ⌥digits only with a selection: on Czech and ABC layouts ⌥digits type characters (@, #, ™); swallowing them always broke typing.
- Cache and history share one store, and the user picks how much of it is kept (Off, Last 20 by default, Last 60, Unlimited). Each entry keeps the full selection and result: this reverses the earlier 60-character label, because the History page is for finding and copying past texts, and how much plain text sits on disk is now the user's choice (Off keeps no results on disk: the file is emptied). Off still keeps the last result in memory, so the cache of the last run works until Retext quits. Saves are debounced and run off the main thread, since an unlimited history of long texts is rewritten as a whole.
- Single instance through a `flock`, not a check of running apps: the kernel drops the lock when the process ends, even after a crash, and a build copy and the installed copy (different paths) still count as one Retext.
- Quality levels over a per-action model choice: one switch steps up model, effort and instructions together, and ↑/↓ in the bar make a stronger run a single keystroke. The level is not remembered between bars, so a Max run never silently carries over.
- Instruction field is an `NSTextField`, not a SwiftUI `TextField`: it takes first responder reliably in the non-activating panel.
- No Apple on-device models or Translation: they don't cover every language, and Apple Intelligence isn't available in every system language.
- Copy instead of paste when the selection holds an image: pasting rich text from Claude's plain answer would drop the image or turn it into its file name; a copy keeps the original intact.
- Update check over a bundled updater (Sparkle): no dependency and no background downloads; one daily GET that the user can turn off, and the menu item opens Settings → About, which links the release page. Nothing is downloaded or installed: Retext is built from source until a signed release exists.
- Demo runs on sample data, never the user's files: `--demo` screenshots must show no real settings, history or paths, and a demo must never overwrite or trim the user's settings.json, history.json or usage.json.
- The bar shortcut as any key code and modifiers, with minimal validation: refused only where it would break typing, a shortcut every Mac uses (⌘C, ⌘V, ⌘Z, Spotlight, input sources, Finder search) or Retext's own ⌥1…⌥9. Other clashes are left to the user, as the General footer says.
- Update-check state in `UserDefaults`, not settings.json: it is app state, not a setting, and must not travel with an exported settings file.
- Preview off by default, diffed by words with a cap: the default stays one keystroke to a replaced selection; words read better than characters for a rewrite, and the LCS is capped (whole-block fallback) so a huge change can't stall the main thread or memory.
- Identity in `Info.plist` (`CFBundleIdentifier`, `RetextRepository`), with the Keychain key moved add-only and read back before the old item goes: a fork changes plist keys, not code, and a move racing a key saved in Settings can never overwrite the newer key or lose the only copy.
- Planned distribution as a Developer ID signed, notarized DMG plus a Homebrew tap (for now, build from source), not the Mac App Store: the event tap and Accessibility don't fit the sandbox, and the app shells out to `claude`.
- Bordered pop-ups and pull-downs as `NSPopUpButton` wrappers (`PopUpPicker`, `PullDownButton`), not SwiftUI `Picker` or `Menu`: in a grouped `Form` on macOS those draw borderless whatever their style, unlike System Settings.
- Action reordering with `onDrag`/`onDrop` and a `DropDelegate`, not `onMove`: `onMove` does nothing in a grouped `Form` on macOS, and moving the row as soon as the drag enters another shows the new order before the drop.
