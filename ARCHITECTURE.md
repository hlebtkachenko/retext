# Architecture

## Flow
1. `Hotkeys` (a session `CGEvent` tap) always takes the bar shortcut (⌥Space by default, ⌃⌥Space in Settings → General), so it wins over another app's hotkey for the same combo. ⌥1…⌥N (N = number of actions) are taken only when the frontmost app's focused element has a non-empty selection, read from `AXSelectedText`, else from WebKit's text-marker selection (`AXSelectedTextMarkerRange`, as in Mail and Safari) (0.1 s AX timeout); otherwise the key passes through, so Czech ⌥2 = @ still types. The bar shortcut calls `PopupController.trigger()` (menu); ⌥N calls `trigger(index)` and skips the menu (with the menu open, it runs on the selection already read).
2. `SelectionIO.read()` sends ⌘C to get the selected text plus the RTF attributes of its first character, then restores the clipboard; Accessibility on the source app's focused element gives the screen bounds, and the text when ⌘C yields nothing.
3. `PopupController` shows a non-activating `KeyPanel` hosting `PopupView`: a Liquid Glass capsule with an instruction field (focused, an AppKit `NSTextField`) followed by the action buttons, 8 pt below the selection, left-aligned, flipped above when there is no room, under the whole text field when the app's selection bounds are missing or fall outside the field (Electron and web apps), at the mouse pointer when neither is known. The panel takes the hosting view's fitting size and only grows while open. Typing goes to the field; ←/→ move to the buttons only while it is empty; Return runs the instruction or the highlighted button. A chip at the right end shows the quality level: it starts at the default level each time the bar opens, ↑/↓ step it (clamped, wherever the highlight is, without moving the cursor), a click cycles it. Electron apps expose their tree only after `AXManualAccessibility` is set: with "Improve Electron app support" on (default), Retext sets it on every app switch so the ⌥N check works before the first bar; off, it is set only when the tap or `SelectionIO.read()` reads. AX calls use a 0.1 to 0.2 s messaging timeout. The original app stays frontmost.
4. `Engine` (RetextCore) builds a `Job` for the active `Provider` and the run's `Level` (the bar's level, or the default level for ⌥N without the bar): model and effort from `RetextSettings.model(for:)` (Claude Code: Medium `haiku`, High `sonnet`, Max `opus`; ChatGPT: built-in `Codex.defaultModels`, overridable per level; Custom: the user's model per level) and system prompt (task + the level's add-on for High and Max + content rules + protected words + the style for the frontmost app's bundle id).
5. Cache: the key is SHA-256 of provider (Custom adds its base URL) + model + effort + prompt version + system prompt + text. A hit in `history.json` skips the provider and counts as a cache hit (with "Keep history" off, the cache is neither read nor written). Otherwise `ProviderRunner` sends the job to the active provider's runner. Claude Code: `ClaudeRunner` runs `claude -p --model haiku|sonnet|opus --effort <level effort> --output-format json` with user settings, hooks, plugins, MCP and tools disabled; `claude` is the Settings path override, else `command -v claude` in a login shell (once), else the usual install paths. Text goes in on stdin inside a tag with a random suffix (`<text-1a2b3c4d>`), so selected text can't close the block; timeout per level (`Level.timeout`: 60 s at Medium and High, 120 s at Max), Esc cancels. Failures are sorted from the JSON `result` and stderr into not found, not logged in, usage limit, unknown model or other (`ClaudeFailure`). `result`, tokens and `total_cost_usd` (≈ list price) are recorded in `usage.json` and the history. ChatGPT: `CodexRunner` runs `codex exec --ephemeral --json` (`Codex.arguments`; no session files) with `-s read-only` (no file writes), the shell and other tool features `--disable`d (read-only alone still let the model run shell commands), web search off, the skills list left out of the prompt (`skills.include_instructions=false`), the system prompt as `developer_instructions` (a TOML basic string, `Codex.tomlString`), and `CODEX_HOME` set to `~/Library/Application Support/Retext/codex-home`, where Retext creates only a symlink `auth.json` to Codex's own (Codex writes its own state and logs there) (`$CODEX_HOME` from the app or the login shell, else `~/.codex`), so the user's config, `AGENTS.md` and MCP stay out and token refreshes land in the real file; its working directory is the empty `codex-home/work`, so no project `AGENTS.md` is picked up either; the codex directory goes first on `PATH`, since an npm install is a Node script. The result is the last `agent_message` in the JSONL, tokens come from `turn.completed`; `turn.failed`/`error` lines are sorted by `Codex.classify` (a 401 is not logged in, "model is not supported" an unknown model). Custom: `APIRunner` POSTs to `{base}/chat/completions` (`OpenAICompatible.body`) with the Keychain key saved for that endpoint's scheme, host and port (`CustomProviderSettings.keyAccount`) as a Bearer token, so a base URL pointed at another server gets no key; an http URL works only for a local or private-network host (`CustomProviderSettings.isLocal`, which also makes the key optional), and redirects are followed only to the same scheme, host and port (`OpenAICompatible.allowsRedirect`); 401/403 is a rejected key, 429 the limit, a 404 about the model an unknown model. Both have the same per-level timeouts and Esc cancel as Claude Code; the answer is recorded the same way, with no cost.
6. `Engine.checkLayout` (grammar and translate only): a one-line input whose result has line breaks gets them joined into one line, unless an app style applies (it may ask for a layout); a grammar result longer than 1.5 × input + 20 characters is treated as containing extra text (a note to the user) and fails with `ClaudeFailure.extraText`, so nothing is pasted. Typed instructions pass through. Then, if the normalized result equals the normalized input, a "No changes needed" bubble shows and nothing is pasted or copied.
7. `SelectionIO.replace()` puts the result on the clipboard as RTF in the original attributes plus plain text (marked transient), re-activates the app, sends ⌘V, then restores the old clipboard, marked `org.nspasteboard.TransientType` so clipboard managers skip it. Rich-text apps keep the original font, size and colour; plain-text fields take the plain string. ⌘Z undoes it.
8. If the selection is read-only (no text role, `AXSelectedText` not settable, no `AXEditableAncestor`: web pages, PDFs, received mail), holds an image or other attachment (`Selection.hasAttachment`: U+FFFC in the AX text or the copied plain text, or an attachment in the copied RTF or RTFD; pasting text would turn a Mail signature image into its file name), or changed while Claude worked (checked on the source app, not the system-wide focus, which can be Retext's field; compared with the Accessibility text from the read, else with the copied text), the result is copied instead of pasted. While the "Copied" bubble shows (4 s), the event tap turns ⌘Z into "restore the previous clipboard"; outside that window ⌘Z is untouched.

## Files
- `Sources/RetextCore/Settings.swift`: `RetextSettings` (actions, default level, app styles, protected words, bar shortcut, claude path, history, Electron and update-check switches, `onboarded`), defaults (the third action follows the Mac's first language), the built-in prompt per action kind (Reset Prompt), protected-word list parsing, JSON load and save (load moves untouched 1.2.0 default prompts and the old Mail style to the current defaults), import validation (must decode and have `actions`), `Store` paths. `onboarded` decodes as true when the key is missing, and load sets it when settings.json is missing but history.json or usage.json exists, or when settings.json can't be decoded (load first copies it to `settings.json.invalid`, keeping an earlier copy), so only a new install sees the welcome window.
- `Sources/RetextCore/Engine.swift`: `Level` (model, effort, prompt add-on), model short names, system prompt, boundary-tag wrapper, cache key, no-change normalization, `claude -p` JSON parsing, error classification and per-provider messages.
- `Sources/RetextCore/Providers.swift`: `Provider`, `ProviderModel`, `CustomProviderSettings` (base URL, models, presets), `RetextSettings.model(for:)`, `Codex` (default models, `codex exec` arguments, TOML escaping, JSONL parsing, `debug models` list, error classification), `OpenAICompatible` (request body, response and error parsing, HTTP status mapping).
- `Sources/RetextCore/LevelTimeout.swift`: `Level.timeout`, how long one `claude -p` run may take.
- `Sources/RetextCore/Updates.swift`: `Release` (GitHub's `releases/latest` answer) and `Version.isNewer` (tag vs. `CFBundleShortVersionString`).
- `Sources/RetextCore/History.swift`: history/cache (20 entries) and per-day usage counters (last 90 days).
- `Sources/Retext/RetextApp.swift`: app entry, menu-bar menu (actions with ⌥N that run on the selection, Recent, usage line opening Settings → Usage, clickable Accessibility / active provider problems shown only when present, "Update available" when the update check found a newer release, Welcome…, Settings…; `isInserted` binding writes only real changes, since SwiftUI writes it back on every scene update), shortcut event tap.
- `Sources/Retext/AppState.swift`: shared settings, history and usage, saved on change; the active provider's status (checked again when provider settings change), the available update.
- `Sources/Retext/Welcome.swift`: `AppWindows` (the activation policy shared by Settings and Welcome), the welcome window (first launch, `--demo welcome`), and the live Accessibility and provider status rows used there and in General.
- `Sources/Retext/Updates.swift`: `UpdateChecker`: at launch and 30 s after the Mac wakes, at most once a day and only with "Check for updates" on, GETs `api.github.com/repos/hlebtkachenko/retext/releases/latest` (ephemeral session, `User-Agent: Retext/<version>`, nothing else). The last check time, latest version and its page are kept in `UserDefaults` (`co.hleb.retext`), so a relaunch the same day still shows the menu item. A `swift build` binary (no version) never checks.
- `Sources/Retext/Popup.swift`: state model (including the run's level), SwiftUI view with the level chip, instruction field, panel, placement, keyboard and click handling, run flow.
- `Sources/Retext/SettingsView.swift`: native settings window (sidebar: Actions, App styles, Protected words, Engine, General, Usage). Actions: rows are buttons (keyboard and VoiceOver), Reset Prompt, Restore Default Actions, SF Symbol name check. App styles: app picker from running apps and /Applications, ~/Applications, /System/Applications (scanned off the main thread), with icons. Protected words: comma-separated add field and Paste List…. Engine: provider picker, default level with what each level runs for that provider, then per provider: Claude Code path override and Test; Codex path override, ChatGPT login status, model and effort per level (models from `codex debug models`) and Test (checks `codex login status` first); custom API base URL with presets, API key (SecureField, saved to the Keychain, shown only as "Saved"), model and optional effort per level, and Test. Each Test is a Medium run with input "ok". General: Permissions, "Open at login" (reads and sets `SMAppService.mainApp`, off until the user turns it on), "Show in menu bar" (`MenuBarExtra(isInserted:)`; with it off, reopening the app shows Settings via `applicationShouldHandleReopen`), bar shortcut, "Keep history" and Clear History, "Check for updates", Backup (export and import through `NSSavePanel`/`NSOpenPanel` in the settings.json format, reset; both keep `onboarded`, import also keeps the Claude Code and Codex paths and the custom API base URL, so an imported file can't redirect the saved key), Advanced ("Improve Electron app support"), About. Destructive buttons ask first. Switches to the `.regular` activation policy while open.
- `Sources/Retext/Selection.swift`: Accessibility read, clipboard fallback, paste.
- `Sources/Retext/Claude.swift`: `claude` discovery, `claude --version`, and the `claude -p` runner.
- `Sources/Retext/Codex.swift`: `codex` discovery (login shell, Homebrew, `~/.local/bin`, nvm), the private CODEX_HOME, the `codex exec` runner, `codex login status`, `codex --version` and `codex debug models`.
- `Sources/Retext/API.swift`: the OpenAI-compatible runner (ephemeral URLSession, whole-call timeout) and `Keychain` (the custom API keys, generic passwords `co.hleb.retext` / `custom-api-key:<scheme>://<host>[:port]`).
- `Sources/Retext/CLI.swift`: `CommandLocator` (override, login shell `command -v`, candidates) and `Subprocess.run` (stdin, stdout and stderr, per-run stop on cancel or timeout) shared by Claude Code and Codex.
- `Sources/Retext/ProviderRunner.swift`: dispatch to the active provider's runner, and `ProviderStatus` (local readiness check for the menu, welcome window and General).
- `Resources/AppIcon.icon`: the Liquid Glass app icon (Icon Composer format: solid brand fill, R and cursor layers with glass). `build.sh` and `scripts/release.sh` compile it with `actool` into `Assets.car` (needs Xcode 26 or later) and fail if that step fails. `Resources/AppIcon.icns` is the full-size fallback rendered from it.
- `scripts/make-icon.swift`: writes the icon's glyph SVGs, renders `AppIcon.icns` from the compiled glass icon and the launch images in `docs/images/`.
- `scripts/release.sh`: builds a universal app, signs it with Developer ID, notarizes and staples it, and packs it into a signed, notarized DMG (see `docs/RELEASING.md`).
- `.github/workflows/release.yml`: runs `scripts/release.sh` on a pushed `vX.Y.Z` tag and attaches the DMG to the GitHub release; skips the whole run when the release already has `Retext-VERSION.dmg`, so published assets are never overwritten.
- `Casks/retext.rb`: template of the Homebrew cask for the `hlebtkachenko/tap` tap.
- `docs/index.html`: the landing page (GitHub Pages).
- `eval/`: prompt eval set for the quality levels and prompts; see `eval/README.md`.

## Decisions
- Native app over Hammerspoon: SwiftUI Liquid Glass needs a real app; it also removes a dependency.
- ChatGPT through the Codex CLI, not the OpenAI API: it uses the ChatGPT subscription the user already has, and Retext keeps handling no OpenAI credentials (Retext only links the private CODEX_HOME's auth.json to Codex's own, never reads it).
- Every other model through one OpenAI-compatible client: OpenRouter, Ollama, LM Studio, Gemini, Mistral and Groq all speak Chat Completions, so one runner with a base URL covers them. Its key goes to the Keychain, not settings.json, so exporting settings never leaks it, and it is bound to the host it was saved for, so changing or importing a base URL never sends it elsewhere.
- One active provider, not a provider per action or level: the levels stay one switch, and the bar works the same whichever provider runs.
- `claude -p` over a built-in API client: Retext never handles Claude credentials. Uses your own Claude Code login: subscription usage counts against your plan's limits; API-key logins are billed to your account. Cost shown is the list-price equivalent.
- Paste via clipboard over AX `setValue`: works in every app and keeps native undo.
- Plain-text paste was dropped: Mail fell back to its default Helvetica instead of the selection's font.
- Event tap over Carbon `RegisterEventHotKey`: Carbon fails when another app holds the combo; the tap takes precedence.
- ⌥digits only with a selection: on Czech and ABC layouts ⌥digits type characters (@, #, ™); swallowing them always broke typing.
- Cache and history share one store capped at 20 entries.
- Quality levels over a per-action model choice: one switch steps up model, effort and instructions together, and ↑/↓ in the bar make a stronger run a single keystroke. The level is not remembered between bars, so a Max run never silently carries over.
- Instruction field is an `NSTextField`, not a SwiftUI `TextField`: it takes first responder reliably in the non-activating panel.
- No Apple on-device models or Translation: they don't cover every language, and Apple Intelligence isn't available in every system language.
- Copy instead of paste when the selection holds an image: pasting rich text from Claude's plain answer would drop the image or turn it into its file name; a copy keeps the original intact.
- Update check over a bundled updater (Sparkle): no dependency and no background downloads; one daily GET that the user can turn off, and the menu item opens the release page.
- Update-check state in `UserDefaults`, not settings.json: it is app state, not a setting, and must not travel with an exported settings file.
- Distribution as a Developer ID signed, notarized DMG plus a Homebrew tap, not the Mac App Store: the event tap and Accessibility don't fit the sandbox, and the app shells out to `claude`.
